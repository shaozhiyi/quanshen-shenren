## 代码体检（已接进工程根目录，双击即用）

| 入口 | 干什么 | 会不会改文件 |
| --- | --- | --- |
| `统计代码.bat` | 行数统计，写 `docs\代码统计.md` | 只写统计文档 |
| `代码检查.bat` | gdlint 体检 + gdformat 预览 | **不改任何代码** |
| `格式化代码.bat` | gdformat 真格式化（要输 y 确认） | 会重写 `.gd`，先 commit |

当前体检结果（2026-09-09，43 个 `.gd`）：

```
220  class-definitions-order    ← 声明顺序（信号/枚举/常量/变量/方法），纯风格，不建议动
104  max-line-length            ← 超 100 列，注释里居多
  7  function-variable-name      6  max-public-methods
  4  duplicated-load             2  unused-argument      2  max-file-lines
  1  loop-variable-name          1  class-variable-name  1  function-arguments-number
gdformat：42/43 个文件会被重写（未执行）
```

结论：**没有真正的 bug 级问题**，绝大多数是风格分歧。`gdformat` 会顺手把上一轮删掉的空行加回来，
所以没执行；真要统一风格，先 commit 再跑 `格式化代码.bat`，`git diff --stat` 复核即可。
值得单独看的只有 2 处 `unused-argument` 和 4 处 `duplicated-load`（同一资源在多处 `load`，可提成常量）。

## 搬家踩到的坑（下次再挪必看）

导出模板不是靠 exe 同级目录找到的，而是 `C:\Users\<你>\AppData\Roaming\Godot\export_templates\4.7.2.stable`
这个**链接**指向 E 盘那份 1.3G 模板。移动 Godot 目录会让它断掉，表现是导出报
`Cannot export project with preset "Windows Desktop" due to configuration errors`。
修法是重建链接：`mklink /J "%APPDATA%\Godot\export_templates\4.7.2.stable" "E:\游戏工具\Godot\export_templates\4.7.2.stable"`。
注意 **必须用 `/J`（junction）**：`mklink /D`（符号链接）要管理员权限或开开发者模式，普通命令行会被拒。
旧的断链没删，改名成 `4.7.2.stable.old-broken-link` 留在原处，确认无误后可以清掉。

工程内引用旧路径的地方已全部改到新位置：`tools\loc_report.ps1`（新路径优先、旧路径兜底）、
`docs\发布与下载页.md`、`docs\地形与贴物高度.md`。改完实测导出成功（172M，0 error）。
