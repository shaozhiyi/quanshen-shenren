> 记：游戏本体怎么从工程变成一个「点开就能下载」的网页。最后更新 2026-09-02。

## 一次完整上线（三步）

```bash
GODOT="e:/工具/Godot/Godot_v4.7.2-stable_win64_console.exe"
cd /e/游戏大乱斗

# 1) 导出（先落到 out_game.exe，由脚本负责改名）
"$GODOT" --headless --path . --export-release "Windows Desktop" build/out_game.exe

# 2) 打包：旧 exe 进回收站 → 改名 build/神人乱斗.exe → 同步 web/files/{game.exe,readme.txt}
powershell -NoProfile -ExecutionPolicy Bypass -File tools\repackage.ps1

# 3) 发布整个 web/ 目录（在千问办公里说"重新发布下载页"即可，页面代码有改动时才需要）
```

冒烟检查（可选但推荐）：`cd build && ./神人乱斗.exe --quit-after 500` 后 grep `SCRIPT ERROR`，应为 0。

## 目录与入库约定

| 路径 | 是否入库 | 说明 |
| --- | --- | --- |
| `web/index.html` | 是 | 极简页：标题 + **一个**下载按钮 + `说明.txt` 链接，**不放任何游戏介绍**（介绍全在 `说明.txt` 里）；背景是程序化 canvas 黄昏国道，零外链零依赖不用构建；带 `<meta name="robots" content="noindex">` 不让搜索引擎收录 |
| `web/files/game.exe` | 否（`.gitignore`） | 待上传的本体副本，由 `tools/repackage.ps1` 从 `build/` 同步 |
| `web/files/readme.txt` | 否 | `build/说明.txt` 的副本（前端用 `download` 属性还原成 `说明.txt`） |
| `build/` | 否 | 导出产物与玩家可见的 `说明.txt` |

页面上那行体积数字会先 `HEAD files/game.exe` 取真实 `Content-Length`，取不到才用写死值；
写死的默认值就在 `web/index.html` 的 `id="size"` 那个 span 里，换 exe 后一起改。

已经**不再产出 zip 分享包**（2026-09-02 起）：网页直接给单 exe，`build/野生狗奶大乱斗_分享包.zip` 已删除。

## 两个坑

1. **发布超时 ≠ 失败。** `qwenwork_pages_publish` 传 166 MB 的目录时，工具会在 300 秒后报
   `MCP error -32001: idle timeout`，但桌面端仍在后台上传部署；这期间再调用只会得到
   `page is being deployed, cannot publish`。等它部署完再发，就是**同一个域名下的新版本**（不会换 URL）。
2. **Godot 默认导出"工程目录内全部资源"。** 没有被任何脚本/场景引用的素材照样打进 pck。
   瘦身先查这个：`kloppenheim_05_puresky.hdr` 就是这样白占 33 MB，移出后 exe 从 207,532,256 → 173,972,800 字节。
   排查方法：`grep -rn "文件名" scripts scenes`，只被自己的 `.import` 提到就是死资源。
   清 `.godot/imported/` 里的孤儿缓存请逐个文件走回收站，别用 `rm` 通配符。

## 关于「防止查看」

现在能挡住的：

- **代码看不到源码。** 预设里 `script_export_mode=2` = 编译成 `.gdc` 字节码，pck 里没有 `.gd` 文本、注释也不进包。
  实测在 exe 里搜 `func _try_hit_player(from: Vector3` 与 `extends CharacterBody3D` 都搜不到。
- **网页端不剧透。** 下载页只有一个按钮、零介绍、零截图，并带 `noindex`；玩法与设定只存在于玩家主动下载的 `说明.txt`。

还挡不住的：

- **素材仍可解包。** pck 是标准 `GDPC` 格式，`song.mp3` 等按原字节躺在包里，Godot RE Tools 一类工具能整包扒出来。

要做真正的 pck 加密，**必须先自编译导出模板**：Godot 4 的加密密钥是编译进模板的
（`scons platform=windows target=template_release script_encryption_key=<64位hex>`，需要 Python + scons + VS Build Tools，
单个模板约 30~60 分钟），4.7 的命令行**没有** `--export-encrypt-pack` 这种密码式选项。
只在 `export_presets.cfg` 里把 `encrypt_pck` 改成 `true` 而不换模板，导出的 exe 会直接打不开。
密钥文件请放在工程外（如 `%APPDATA%\Godot\export_keys\`）并自行备份：丢了就再也导不出能跑的加密版本，
换一把新键则会让旧包全部失效。
