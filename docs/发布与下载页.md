# 发布与下载页

> 记：游戏本体怎么从工程变成一个「点开就能下载」的网页。最后更新 2026-09-02。

## 线上地址

- 下载页（对外分享用这个）：<https://np4facv7.qwenwork.host/>
- 本体直链：<https://np4facv7.qwenwork.host/files/game.exe>（浏览器会存成 `游戏大乱斗.exe`）
- 玩法说明直链：<https://np4facv7.qwenwork.host/files/readme.txt>（会存成 `玩法说明.txt`）

页面正文里的体积数字会先用 `HEAD files/game.exe` 取真实 `Content-Length`，取不到就回退到写死的值，
所以改完 exe 记得同步改 `web/index.html` 里 `id="size"` 那个 span 和「约 166 MB」那句。

## 一次完整上线（三步）

```bash
GODOT="e:/工具/Godot/Godot_v4.7.2-stable_win64_console.exe"
cd /e/游戏大乱斗

# 1) 导出（先落到 out_game.exe，由脚本负责改名）
"$GODOT" --headless --path . --export-release "Windows Desktop" build/out_game.exe

# 2) 打包：旧 exe 进回收站 → 改名 build/游戏大乱斗.exe → 同步 web/files/{game.exe,readme.txt}
powershell -NoProfile -ExecutionPolicy Bypass -File tools\repackage.ps1

# 3) 发布整个 web/ 目录（在千问办公里说"重新发布下载页"即可，页面代码有改动时才需要）
```

冒烟检查（可选但推荐）：`cd build && ./游戏大乱斗.exe --quit-after 500` 后 grep `SCRIPT ERROR`，应为 0。

## 两个坑

1. **发布超时 ≠ 失败。** `qwenwork_pages_publish` 传 166 MB 的目录时，工具会在 300 秒后报
   `MCP error -32001: idle timeout`，但桌面端仍在后台上传部署；这期间再调用只会得到
   `page is being deployed, cannot publish`。等它部署完再发，就是**同一个域名下的新版本**（不会换 URL）。
2. **Godot 默认导出"工程目录内全部资源"。** 没有被任何脚本/场景引用的素材照样打进 pck。
   瘦身先查这个：`kloppenheim_05_puresky.hdr` 就是这样白占 33 MB，移出后 exe 从 207,532,256 → 173,972,800 字节。
   排查方法：`grep -rn "文件名" scripts scenes`，只被自己的 `.import` 提到就是死资源。
   清 `.godot/imported/` 里的孤儿缓存请逐个文件走回收站，别用 `rm` 通配符。
